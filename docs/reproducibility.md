# Reproducibility

## What can be reproduced from this repository

| Item | Reproducible | Notes |
|---|---|---|
| Inference with the released weights | yes | `pip install` the package; the encoder and reader are downloaded on first use. |
| Training pipeline (feature cache, reader training, resume) | yes, with your own data | `training/`, method in [training.md](training.md). The smoke config runs on CPU with synthetic data and is part of CI. |
| Benchmark tables | numbers: yes, data: you supply it | Scoring is `embed2asr.metrics`; results and settings are in `benchmarks/v0.1.0.json`, tables are generated by `scripts/fill_bench.py`. Test audio is not redistributed; obtain each test set from its owner. |
| Speed table | yes | `benchmarks/speed_v0.1.0.json` holds the measurements and conditions; figure and tables are generated by `scripts/make_perf_svg.py` and `scripts/fill_perf.py`. |
| The released checkpoint bit for bit | no | The training data is not published, and GPU kernels (MIOpen GRU, HIP graphs) are not bitwise deterministic. Retraining with this code gives a similar model, not the same weights. |

## Environment

- Python 3.10+, transformers >= 5.19 (first release with the `embedding_gemma2` model).
- Measurements were taken on one AMD Instinct MI300X, ROCm 7.1, PyTorch 2.10.0 (ROCm build), transformers 5.19.0. Encoder runs in bf16, reader in fp32.
- Inference also runs on CPU and should run on CUDA; neither was used for the numbers in this repository.
- Transcripts can differ by one unit across transformers versions and GPU models; they are stable within one environment.

## Running the benchmark yourself

1. Install from a checkout: `pip install -e ".[eval]"`.
2. Transcribe a test set with the default (per-file) path, either `embed2asr transcribe ... --json` or `Embed2ASR.transcribe`.
3. Normalise and score with `embed2asr.metrics.score`: CER for Mandarin, WER for English, MER for code-switching; rows whose reference contains digits are dropped.
4. For the LM rows add `--lm lm/charlm5.json.gz --lm-alpha 0.25 --lm-beta 1.5 --beam 16` (Mandarin and mixed sets only).

## Training

See [training.md](training.md): `python -m training.prepare_features`, then `python -m training.train --config configs/recipe_v0.1.0.yaml`. The recipe config holds hyperparameters only; point `E2A_CACHE` and `E2A_CKPT` at your own feature cache and checkpoint directory.

## Seeds and determinism

- Sampling order is a pure function of (seed, pass), so a resumed run sees the same data order.
- Default seed: 42.
- Known sources of nondeterminism: GPU kernels, and batch composition in the encoder (see [limitations.md](limitations.md)).

## Reporting rules

- Test splits are evaluated once, for the final selected checkpoint, with decoder settings fixed on development data.
- Greedy and LM results are reported separately.
- CER, WER and MER are never averaged into one number.
- Speed numbers state hardware, batch size, precision and timing scope.
